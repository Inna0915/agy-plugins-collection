# 执行端产出严审清单与打回模板

适用于主控（Antigravity 或 Claude Code）验收 Codex、DSH 或子代理产出的代码、审查结论与双盲方案。审核准绳以当前项目与全局 `AGENTS.md` 为基础，聚焦真实差异、工程红线与返工收敛。

## 审核铁律

1. **只信真实代码与实测，不信口头总结**：先在对应工作树（或扣除基线后的主工作树）核对 `git status`、`git diff` 与验证输出，再对照最终报告或结构化 `handoff`。
2. **保护合法边界，别误杀必要防御**：用户输入、外部不可信数据、网络/IO/生命周期错误处理，以及有可达调用路径证明的真实边界，必须保留；不要为了极简删掉正确性或安全性保障。
3. **按影响分级，省着花返工配额**：只让阻断项触发返工（默认最多打回 **2 轮**）；纯命名/格式偏好列为非阻断建议，不单独消耗返工配额（已有阻断项时可顺带清理，或由主控收口时顺手精简）。

## 红线一：过度防御（标 `[DELETE_OVERDEFENSE]`）

对照真实 Diff 与自报的 `guards_and_fallbacks`：

- **冗余二次校验（阻断）**：上游类型、请求封装、组件 prop 或已知调用方已保证契约，仍新增无证据的判空、`?.`、`?? []`、`typeof`、`Array.isArray` 等兜底。
- **静默吞错掩盖契约故障（阻断）**：用 `|| ''`、`?? []`、`catch { return [] }` 把本应暴露的接口或类型异常伪装成空结果/成功态。
- **无证据的假想加固（阻断）**：没有可达复现或并发场景证据，却新增锁、队列、缓存、重试、防抖或旧版本兼容分支。
- **顺手大改无关代码（阻断）**：大面积重排、格式化或重构与任务无关的代码。
- **漏报或空泛理由（先核契约再决定）**：Diff 新增防御分支却未自报或仅写“以防异常”时，先查真实调用方与契约——确有可达依据则保留，确认上游已保证则打回删除。

## 红线二：不粘锅与半成品（标 `[MUST_FIX]`）

- **假卡壳真甩锅**：代码里有线索可查、属于可逆小决策，或本可先把无阻塞部分做完却中途返回 `needs_input` / `needs_permission`（包括把常规构建/测试误当高危报批）→ 主控直接拍板或明确豁免，原会话打回做完。
- **只盖症状不修根因**：修 Bug 时仅在报错行补 `if (!x) return` 躲过去，未追查上游为何传入非法值 → 打回修根因。
- **改不全与同类漏改**：留下 `TODO`、注释旧代码不删、只改单点不查同类入口/配置/测试/文档，或未按旧说法反搜清掉过时文案 → 打回全仓补齐。
- **推卸验证责任**：未跑必要构建/测试/类型检查就标 `done`，或命令失败时轻飘飘甩一句“可能是历史/环境问题”而不核实是否本次引入 → 打回实测，或由主控复核定性。
- **盲从走歪不吹哨**：任务前提或字面改法与仓库真实契约冲突，却闷头改完不喊停也不给证据提醒 → 打回重评或上报用户校正方向。
- **免责腔污染交付**：执行端总结里的“理论上应该没问题，建议你再测一下”“注意以下假想风险”等无实证套话，主控交付给用户前必须剥离。

## 复发拦截与反向审查过滤

- **复发问题机械化拦截（棘轮原则）**：普通小改动不强加单测；但被打回的是实测 Bug、契约违背或反复发生的同类漏改，且仓库已有类型检查、lint 或测试体系时，优先在同一次返工里补一条针对性类型约束或回归守卫测试。
- **反向审查过滤（防迁就过度审查）**：接收执行端的只读 `review` 回执时，主控逐条核对 `[BLOCKING]` 指向的 `文件:行号`、可达输入/操作顺序与违背契约是否真实成立；无法复现、上游契约已保证或多重假想拼凑的条目直接过滤，**不要为了迁就审查意见而给代码堆多余防御**。

## 精准打回模板

打回指令必须逐条可执行，严禁模糊评价：

```markdown
审核未通过，请在本会话中按以下清单直接修复并重新验证：

1. [DELETE_OVERDEFENSE] `src/foo.ts:42`
   - 问题：对 `fetchPage` 返回的 `page.rows` 加了 `(page?.rows ?? [])`，该封装已保证成功返回 `rows`，且未提供反例证据。
   - 改法：改为直接使用 `page.rows`。

2. [MUST_FIX] `src/bar.ts:88`
   - 问题：仅用 `if (!user) return` 跳过异常，未修复上游传入 `undefined` 的根因。
   - 改法：检查 `src/caller.ts:19` 并修复源头传参，同时跑通测试验证。

要求：仅修改上述条目及其直接连带项，不要重构无关代码；修改后实跑验证命令并如实报告结果。
```
